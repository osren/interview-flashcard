#### 1. `extractPdfText(dataUrl)` - **1000-5000ms**

```typescript
// src/utils/extractPdfText.ts (推测实现)
import * as pdfjsLib from 'pdfjs-dist';

export async function extractPdfText(dataUrl: string): Promise<string> {
  const pdf = await pdfjsLib.getDocument(dataUrl).promise;  // 500-2000ms (加载 PDF)
  
  let fullText = '';
  for (let i = 1; i <= pdf.numPages; i++) {
    const page = await pdf.getPage(i);  // 100-300ms per page
    const textContent = await page.getTextContent();  // 50-150ms per page
    const pageText = textContent.items.map(item => item.str).join(' ');
    fullText += pageText + '\n';
  }
  
  return fullText;  // 总计: 1-5 秒（10-30 页 PDF）
}
```

**耗时分解**：
- PDF 加载: **500-2000ms** (取决于文件大小 1-10MB)
- 解析页面结构: **100-300ms** per page
- 提取文本内容: **50-150ms** per page
- 10 页 PDF: **1500ms**，30 页 PDF: **5000ms**

**瓶颈分析**：
- ⚠️ **阻塞主线程**：PDF.js 在主线程同步解析
- ⚠️ **大文件慢**：10MB PDF 可能需要 5 秒
- ⚠️ **重复提取**：切换简历源时可能重复提取

## 四、优化建议

### 🔴 P0 级（立即优化 - 影响用户体验）

#### 建议 1: **使用 Web Worker 提取 PDF 文本**

**当前问题**：PDF 文本提取阻塞主线程 1-5 秒

**优化方案**：
```typescript
// pdf-extract.worker.ts
import * as pdfjsLib from 'pdfjs-dist';

self.onmessage = async (e: MessageEvent<{ dataUrl: string }>) => {
  try {
    const pdf = await pdfjsLib.getDocument(e.data.dataUrl).promise;
    let fullText = '';
    
    for (let i = 1; i <= pdf.numPages; i++) {
      const page = await pdf.getPage(i);
      const textContent = await page.getTextContent();
      const pageText = textContent.items.map(item => item.str).join(' ');
      fullText += pageText + '\n';
      
      // 报告进度
      self.postMessage({ type: 'progress', page: i, total: pdf.numPages });
    }
    
    self.postMessage({ type: 'complete', text: fullText });
  } catch (error) {
    self.postMessage({ type: 'error', error: error.message });
  }
};

// 主线程
const worker = new Worker('/pdf-extract.worker.js');
worker.postMessage({ dataUrl });

worker.onmessage = (e) => {
  if (e.data.type === 'progress') {
    setProgress(`提取中... ${e.data.page}/${e.data.total} 页`);
  } else if (e.data.type === 'complete') {
    updateResumeExtractedText(resumeId, e.data.text);
    setExtracting(false);
  } else if (e.data.type === 'error') {
    setError('PDF 文本提取失败');
  }
};
```

**预期收益**：
- 主线程不阻塞，用户可继续操作
- 显示提取进度（页数）
- 提取完成前可继续浏览页面

**实施难度**: ⭐⭐⭐⭐ (需要 Worker 配置 + PDF.js Worker 模式)

#### 建议 9: **压缩存储的 PDF Base64**

**优化方案**：
```typescript
// 使用 pako 压缩 Base64
import pako from 'pako';

const compressPdf = (dataUrl: string): string => {
  const compressed = pako.deflate(dataUrl);
  return btoa(String.fromCharCode(...compressed));
};

const decompressPdf = (compressed: string): string => {
  const binary = atob(compressed);
  const bytes = new Uint8Array(binary.length);
  for (let i = 0; i < binary.length; i++) {
    bytes[i] = binary.charCodeAt(i);
  }
  const decompressed = pako.inflate(bytes, { to: 'string' });
  return decompressed;
};
```

**预期收益**：

### 9.3 面试回答模板

**问：如何处理长时间计算任务的用户体验？**

> 我在简历优化页遇到两个长时间任务：PDF 文本提取（1-5秒）和 AI 优化（3-10秒）。
> 
> 我的优化方案是：
> 1. **PDF 文本提取**：使用 Web Worker，主线程不阻塞，用户可以继续操作，显示提取进度（已提取 X/Y 页）
> 2. **AI 优化**：实现模拟进度条（0-90%），每 300ms 增加 5%，让用户看到进度反馈
> 3. **后续计划**：接入 Server-Sent Events 实现流式输出，用户可以实时看到 AI 生成的内容
> 
> 最终用户不再误以为页面卡死，体验显著提升。

**问：如何处理 localStorage 存储限制？**

> 原本将 PDF 以 Base64 存储在 localStorage，5MB PDF 编码后变成 6.67MB，多个 PDF 容易超限。
> 
> 我的解决方案是：
> 1. **迁移到 IndexedDB**：存储容量从 5-10MB 扩展到无限制，异步 API 不阻塞主线程
> 2. **元数据分离**：PDF 数据存 IndexedDB，元数据（文件名、大小、上传时间）存 Zustand (localStorage)
> 3. **压缩优化**：使用 pako 压缩 Base64，存储大小减少 40-50%
> 
> 最终支持存储更多 PDF，且不影响性能。

**问：如何优化外部网站的 iframe 加载？**

> 在线简历 Tab 嵌入了外部网站（Vercel 部署），首次加载需要 0.5-2 秒。
> 
> 我的优化方案是：
> 1. **预加载**：页面加载后 2 秒用 `<link rel="prefetch">` 预加载资源
> 2. **保持挂载**：首次访问后保持 iframe 挂载，切换 Tab 只是 `display: none`，避免重复加载
> 3. **降级方案**：提供"新窗口打开"按钮，网络慢时可以直接跳转
>
