# 滴滴企业版商旅 · 前端实习描述

> 依据 `滴滴实习工作总结.md` 整理 · 总分结构  
> 时间：2026.01 — 2026.07（约 5.5～6 个月）  
> 岗位：前端开发实习生 · 部门：商旅体验

---

## 一、总述

在滴滴企业版商旅实习期间，我同时参与 **配置中台（甲子 `jiazi`）** 与 **机火核心预订端（`fe-esflight` / `fe-estrain`）** 的前端开发，形成「B 端配置 + C 端预订」双线交付能力。

**甲子后台**：累计约 **160 次提交**、独立/主导 **16 条 feature 分支**，成果随 **15 次正式 release** 上线（平均约每 11 天一次），主战场为机票政策，并辐射用车、供应商、资源、会员等配置域。

**机火预订端**：6 月底至 7 月底连续交付并上线 **3 项需求**——机票侧多品类分享、机票侧超标次数预警、火车票侧联系人手机号联动出行人——分别对应增长转化、差异化管控、代订提效三类业务目标。

技术栈以 **React** 为主；后台侧重 Ant Design + Service 分层，预订端覆盖 H5 / 小程序多端与埋点联调。日常使用 **Cursor + 项目内 Agent Skills** 加速 PRD 解读、CRUD 脚手架与周报汇总，接口对齐、业务规则与上线质量仍由人工 Review / 自测负责。整体角色以前端协助交付为主，强调代码 ownership 与稳定发版。

### （二）机票预订端（`fe-esflight`）

**定位**：滴滴商旅核心品类 C 端；本人负责机票侧，需求已上线。

#### 1. 多品类分享场景（06 底—07 中）

**总目标**：在不干扰主流程前提下扩大分享感知，带动同事预订转化。

**分项工作（机票）**：

- 入口扩展：预订成功页、订单详情、订单列表、商品详情增加「邀请同事」
- 规则落地：改签&多人、改签&假中转等场景屏蔽；望月控制激励展示
- 数据可归因：分享展现/点击埋点，按入口区分 place
- 体验细节：成功页按钮文案、商品详情卡片文案与失效兜底

#### 2. 超标次数预警（同期上线）

**总目标**：以人维度超标次数/排名做预订警示，支撑差旅差异化管控。

**分项工作（机票）**：

- 触发链路：航班报价页点「预订」、填单页提交、改签选航班
- 防打扰：同一预订行为最多弹一次（会话标识或品类频控）
- 文案与口径：次数版 / 排名版；对齐 RC 超标且企业支付成功计入等规则

## 三、分述 · 能力与协作方式

### 1. 交付方式

- 按 feature 分支开发，频繁同步主干，跟随团队 release 节奏合入
- 需求理解：对齐 PRD / 望岳状态；复杂规则（屏蔽矩阵、弹窗频控、选号空态）人工核对后实现
- 质量保障：自测主路径 + Code Review；体验类问题以最小 diff 修复为主

### 2. AI 辅助工程化（实习中后期重点能力）

| 场景 | 怎么用 | 人怎么把关 |
|------|--------|------------|
| 需求理解 | Cursor / Cooper 类 Skill 读 PRD、抽字段与流程 | 对照 PRD 截图与业务口径核对 |
| 页面开发 | 项目内 `crud-page` / `service-api` 等 Skill 生成列表/表单/Service 骨架 | 对齐 Ant Design 规范与既有模块模式，CR 后合入 |
| 缺陷定位 | Agent 辅助排查交互/入参问题 | 本地复现 → 最小 diff → 回归 |
| 交付管理 | weekly-report + Git / 望岳进度自动汇总 | 过滤范围、补充业务解读 |

**原则**：AI 负责提效与减少重复劳动；业务规则、边界 case、上线结果由人负责。典型落地：机票报价实验排序模块从 PRD 到页面骨架，AI 压缩冷启动，人工补齐实验组/规则逻辑。

### 3. 技术侧重点

| 端 | 重点 |
|----|------|
| 甲子后台 | React + Ant Design；列表/表单 CRUD；Service 分层；路由与模块拆分；AI 脚手架 |
| 机火预订端 | 多端（H5/小程序）；预订链路状态与弹窗；埋点；脱敏与边界态 |

### 4. 双线价值一览

| 业务线 | 场景类型 | 代表结果 |
|--------|----------|----------|
| 甲子 | 配置与定制 | 16 feature / 15 release 稳定进产 |
| 机票 C 端 | 增长 + 管控 | 分享扩入口、超标预警已上线 |
| 火车 C 端 | 代订提效 | 联系人选号已上线 |
| 工程方法 | AI + 规范约束 | PRD→骨架半自动化，质量人工门禁 |
