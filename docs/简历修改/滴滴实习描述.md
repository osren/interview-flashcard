# 滴滴企业版商旅 · 前端实习描述

> 依据 `滴滴实习工作总结.md` 整理 · 总分结构  
> 时间：2026.01 — 2026.07（约 5.5～6 个月）  
> 岗位：前端开发实习生 · 部门：商旅体验

---

## 一、总述

在滴滴企业版商旅实习期间，我同时参与 **配置中台（甲子 `jiazi`）** 与 **机火核心预订端（`fe-esflight` / `fe-estrain`）** 的前端开发，形成「B 端配置 + C 端预订」双线交付能力。

**甲子后台**：累计约 **160 次提交**、独立/主导 **16 条 feature 分支**，成果随 **15 次正式 release** 上线（平均约每 11 天一次），主战场为机票政策，并辐射用车、供应商、资源、会员等配置域。

**机火预订端**：6 月底至 7 月底连续交付并上线 **3 项需求**——机票侧多品类分享、机票侧超标次数预警、火车票侧联系人手机号联动出行人——分别对应增长转化、差异化管控、代订提效三类业务目标。

技术栈以 **React** 为主；后台侧重 Ant Design + Service 分层，预订端覆盖 H5 / 小程序多端与埋点联调。

同期按团队 **AI 编码规范**（`fe-estrip-ai-coding-spec`：Rules + Agent 约束 + Skills）开展日常开发：大模型与团队 Skills 协同完成「读 PRD → 出方案/任务 → 规范编码 → 质检」，样式还原与业务边界由人工把关。整体角色以前端协助交付为主，强调代码 ownership 与稳定发版。

#### 2. 超标次数预警（同期上线）

**总目标**：以人维度超标次数/排名做预订警示，支撑差旅差异化管控。

## 三、分述 · 能力与协作方式

### 1. 交付方式

- 按 feature 分支开发，频繁同步主干，跟随团队 release 节奏合入
- 需求理解：对齐 PRD / 望岳状态；复杂规则（屏蔽矩阵、弹窗频控、选号空态）人工核对后实现
- 质量保障：自测主路径 + Code Review；体验类问题以最小 diff 修复为主

### 2. AI 辅助开发实践（实习中后期重点能力）

> 口径对齐团队实际：`fe-estrip-ai-coding-spec` + 机火 AI 建设实践。  
> 写「大模型 + 团队 Skills 协同开发」的整段工作面，不抄旧简历 OpenSpec/SSD，不落到某个具体需求细节。

**定位**：在商旅前端团队 AI 编码规范约束下，用大模型协同团队 Skills 做日常需求开发与问题排查——**规范先于生成，Skills 承载流程，人守质量门禁**。

#### 整体工作面

| 维度 | 内容 |
|------|------|
| 规范底座 | 业务仓以 submodule 接入团队 `fe-estrip-ai-coding-spec`：Rules（MPX 模板/样式/星河兼容/ESLint 等）+ Agent 约束（`CLAUDE.md` / `AGENTS.md`：先查再改、最小改动、可验证）约束模型行为 |
| Skills 协同 | 按研发链路调用团队 Skills：Cooper 读 PRD、workflow-hybrid 走「需求 → 设计 → 开发 → 总结」、create-page / create-component 出规范骨架、code-review 质检；运维侧可用 incident-triage 等做告警定位 |
| 开发方式 | **大模型 + Skills 协同待开发**：先澄清目标/边界/风险并出 plan，再最小实现；UI 偏设计还原校验，逻辑偏可验证改动；样式与多端/星河兼容常需人工微调 |
| 覆盖范围 | 贯穿机火预订端与甲子日常交付——需求理解、代码定位、骨架生成、联调辅助、线上告警排查，缩短冷启动与多仓定位成本 |

#### 人机分工原则

| 大模型 + Skills 承担 | 人把关 |
|----------------------|--------|
| PRD / 接口结构化解读，技术方案与任务拆解草案 | 确认目标、范围、非目标与风险（尤其主链路） |
| 按组内规范生成页面 / 组件 / 改动草案 | 对齐既有模块模式；样式还原与星河/多端兼容微调 |
| 调用链定位、影响面分析、告警轨迹梳理 | 确认修复方案、自测回归、CR 后合入发版 |

**原则**：规范与 Skills 决定模型「怎么写」；人决定「写对没有」并承担上线结果。组内实践表明：业务逻辑草案可复用度往往较高，样式与端兼容是人工投入重点。

### 3. 技术侧重点

| 端 | 重点 |
|----|------|
| 甲子后台 | React + Ant Design；列表/表单 CRUD；Service 分层；路由与模块拆分；规范约束下的 AI 辅助开发 |
| 机火预订端 | 多端（H5/小程序）；预订链路状态与弹窗；埋点；脱敏与边界态；团队 AI Spec / Skills 协同开发 |

### 4. 双线价值一览

| 业务线 | 场景类型 | 代表结果 |
|--------|----------|----------|
| 甲子 | 配置与定制 | 16 feature / 15 release 稳定进产 |
| 机票 C 端 | 增长 + 管控 | 分享扩入口、超标预警已上线 |
| 火车 C 端 | 代订提效 | 联系人选号已上线 |
| 工程方法 | AI 规范开发 | 大模型 + 团队 Spec/Skills 协同，质量人工门禁 |
