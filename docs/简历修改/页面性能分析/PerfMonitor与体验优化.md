# PerfMonitor 性能监控与体验优化

> 业务侧运行时监控与真测优化说明（同事口径整理）  
> 代码锚点：`src/utils/perf-monitor.js`  
> 上报通道：Omega  
> 与 Skill 关系：**运行时真测轨** —— 和 `page-performance-analysis`（静态分析轨）互补，共同构成「性能监控与体验优化」

---

## 1. 定位

搭建 **PerfMonitor** 性能监控体系，把「跨页链路 / 同页 Web Vitals / 关键接口耗时」统一打点并经 Omega 上报，再据此做首页、列表页与稳定性优化，形成可量化的体验收益。

一句话：

> Skill 负责「读代码估瓶颈」；PerfMonitor 负责「线上/真机量出来、再改到数字下降」。

---

## 2. 监控体系能力

### 2.1 核心模块

| 项 | 说明 |
|---|---|
| 实现 | `src/utils/perf-monitor.js` |
| 跨页打点 | 如 home → list 全链路 `home_to_list_complete` |
| 同页指标 | LCP / FCP |
| 接口维度 | 关键接口耗时（如首页 `getHomeData`） |
| 上报 | 统一经 **Omega** 上报，便于看板与对比 |

### 2.2 指标分层

```
┌─────────────────────────────────────────────┐
│ 跨页链路                                     │
│   home_to_list_complete（首页→列表完成）       │
└──────────────────────┬──────────────────────┘
                       ▼
┌─────────────────────────────────────────────┐
│ 同页体验（Web Vitals 自监控）                  │
│   FCP / LCP（H5 + 星河双端）                   │
└──────────────────────┬──────────────────────┘
                       ▼
┌─────────────────────────────────────────────┐
│ 关键路径拆解                                   │
│   关键接口耗时 · 缓存命中直渲 vs 接口返回         │
└─────────────────────────────────────────────┘
```

## 3. 首页优化

| 动作 | 内容 |
|---|---|
| 自监控 | 自建 LCP / FCP 采集，不依赖单一端能力 |
| 环境抽象 | 封装环境判断 class，**H5 与星河**双端均可输出指标 |
| 接口埋点 | 接入 `getHomeData` 关键接口耗时 |
| 路径瘦身 | 定位并剥离拖长 LCP 的接口（如 `privacyPopList` 的耗时累积）—— 非首屏关键请求不再阻塞 / 污染 LCP 口径 |

**可讲决策**：LCP 应对「用户感知的最大内容」，隐私弹窗类接口不应计入首屏关键路径。

---

## 4. 列表页优化

| 动作 | 内容 |
|---|---|
| 双路径覆盖 | 「接口返回」与「缓存命中直渲」两条进入路径均上报指标 |
| 口径修正 | 修正切日期重渲场景的统计口径，避免误报 / 漏报 |
| 量化收益 | 首屏 LCP：**1400ms → 1160ms（↓17%）** |

**可讲决策**：缓存直渲与网络返回是两条不同关键路径，监控漏一条就会「优化了却看不出 / 看错数」。

---

## 5. 稳定性与卡顿

| 项 | 内容 | 结果 |
|---|---|---|
| flight-detail-refactor | 修复 `reportRender` 报错；补充最长进入耗时埋点 | 稳定性 + 可观测 |
| 星河底部菜单切换 | 排查并优化排序逻辑导致的卡顿 | 卡顿改善约 **27%** |

---

## 6. 与 page-performance-analysis Skill 如何拼成闭环

| 阶段 | 谁做 | 产出 |
|---|---|---|
| 定位嫌疑 | Skill 静态分析 | 函数耗时梯队、串行瀑布、P0 建议 |
| 度量基线 | PerfMonitor + Omega | FCP/LCP、跨页、接口耗时 |
| 落地改造 | 业务代码改动 | 剥离非关键接口、修口径、优化排序等 |
| 验收 | PerfMonitor 前后对比 | 如列表 LCP ↓17%、菜单卡顿 ↓27% |

```
Skill 估瓶颈 ──▶ 改代码 ──▶ PerfMonitor 验数字 ──▶ 再迭代
```

此前 Skill 文档写「运行时插桩待演进」—— **业务仓内 PerfMonitor 已补上真测轨**；Skill 侧仍可不内嵌 APM，保持「分析助手」边界。
