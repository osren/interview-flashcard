---

## 一句话目标

> 在**任务效果基本不下降**的前提下，显著降低大模型 Token 消耗；方案越**通用、可迁移**，价值越大。

---

## 背景

大模型已在研发、客服、运营、数据分析、知识问答、办公提效等场景广泛使用，Token 消耗成为 AI 规模化落地的重要成本因素。

很多场景里，大模型并不是因为任务本身复杂而消耗大量 Token，而是因为：

- 上下文输入过长
- 历史对话重复携带
- Prompt 结构冗余
- 文档检索不精准
- 工具调用失败重试
- 模型路由不合理

导致「**完成同样任务，花了不必要的 Token**」。

---

## 参赛要求

- **任务场景不限**：可选研发问答、代码生成、文档总结、客服问答、数据分析、知识库问答、多轮 Agent 等任意方向
- **效果约束**：效果基本不下降
- **加分项**：方案通用、可跨场景迁移

---

## 建议切入方向（七选一或多方向组合）

### 1. 上下文压缩与选择

如何只把当前任务真正需要的信息交给模型，而不是全量塞入历史对话、文档或代码？

### 2. Prompt 精简与结构优化

如何减少重复提示词、冗余规则和低价值示例，同时保持输出稳定性？

### 3. RAG / 检索优化

如何提升召回片段的相关性，减少无关文档、重复片段和长文本噪音？

### 4. 多模型与分阶段路由

如何用小模型、规则、缓存或工具完成简单判断，把大模型调用留给真正需要的环节？

### 5. 缓存与增量上下文

如何复用稳定上下文、只传递变化部分，减少多轮任务中的重复 Token？

### 6. Agent 工具调用优化

如何减少无效工具调用、失败重试和无意义的中间推理输出？

### 7. 通用 Token 评估框架

如何构建一套可复用的 Token 成本、质量、时延、成功率评估方法？
