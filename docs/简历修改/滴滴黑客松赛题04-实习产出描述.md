## 一、总述

针对「任务本身不难，却因上下文过长、Prompt 冗余、路由不当产生无效 Token」的问题，在 **2026 滴滴黑客松大赛赛题 04** 提出并推进 **分层 Token 治理框架（Tiered Token Governance）**：路由先行 → 上下文裁剪 → 动态 Prompt → 模型分级 → 输出约束 → 结果缓存。

以商旅告警降噪为真实样板：在 **宁可误报不可误杀、每条告警仍需调模型** 的约束下，降本主战场定为 **单次调用瘦身 + 工程链路零 LLM 化 + 结果复用**，而非简单少调模型。配套 Eval 门禁，保证 Token 下降时准确率/漏报不恶化。

另输出可迁移扩展：**任务级 Token 预算编排**（语义缓存 / 分层 RAG / Agent 工具失败分类），服务多轮问答场景。

**诚实口径**：路由 + `_base`+key 动态 Prompt 已有工程基础；字段裁剪/指纹缓存/成本看板为 P0/P1 规划；收益数字（如单次 ↓~70%）为估算，需埋点校准。
